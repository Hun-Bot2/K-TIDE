# Codex 작업 지시: M1 학습 데이터 v2 — 문체·범위 보완

권장 설정: `gpt-6.2-sol`, reasoning **high**. `prompts/codex_m1_lecture_only_qa.md`의 모든 규칙(근거·금지 목록·두 답변 버전·출력 형식)을 그대로 따른다.
이 지시문은 v1 결과의 문제만 보완한다. v1 파일은 `qa_v1.jsonl`로 이름을 바꿔 보존하고, 결과를 `qa.jsonl`에 새로 쓴다.

---

## v1 검증 결과 (Claude)

- 누출·형식은 문제없다: unseen 개념 0, 평가셋과 근접 중복 0(최대 유사도 0.5, 1건), 길이 위반 0, 두 버전 쌍 일치 294/294.
- 그러나 학습하면 성능과 무관한 **문체 차이**가 생길 문제가 있다.
  1. 질문 294개 중 **259개가 "~나요?/~가요?" 존댓말**이다. 평가에서 쓰는 질문은 짧은 평서형("X란 무엇인가?", "X의 역할은?", "X와 Y의 차이는?")이다.
  2. 질문 42개와 답변 34개에 "**강의에서는 / 강의의 / 강의 예시는**" 같은 표현이 들어 있다. 평가 질문은 강의를 언급하지 않으므로, 모델이 답에 강의를 언급하는 습관을 배우면 안 된다.
  3. **정의 문항이 35개**(QA가 있는 개념 167개 중 35개만 정의 문항 보유)뿐이고, 원리 문항(78개)에 치우쳐 있다. 강의 구현 세부(예: Dropout 적용 순서)처럼 지나치게 지엽적인 질문도 있다.
  4. 개념당 QA가 대부분 1~2개다(최대 8개 허용).

## 보완 규칙

1. **질문 문체:** 시험 문제처럼 짧은 평서형으로 쓴다. 존댓말 의문형(~나요?, ~가요?, ~까요?)을 쓰지 않는다.
   예시 형태: "X란 무엇인가?", "X의 역할은?", "X를 사용하는 이유는?", "X는 어떻게 동작하는가?", "X와 Y의 차이는?",
   "X의 한계 한 가지는?", "~하면 어떤 문제가 생기는가?", "X는 항상 좋은가?"
2. **강의 언급 금지:** 질문과 답변 모두 "강의", "강의에서", "슬라이드", "수업" 같은 표현을 쓰지 않는다. 내용 근거는 `evidence`로만 남긴다.
3. **정의·역할 우선:** 강의에 정의나 역할 설명이 있는 개념은 **모두** 정의 또는 역할 문항을 최소 1개 갖는다.
4. **범위:** 개념의 핵심(정의, 목적, 원리, 비교, 한계)을 묻는다. 특정 코드 구현 순서나 실습 설정값처럼 지엽적인 질문은 만들지 않는다(그 개념의 핵심이 아닌 경우).
5. **양:** 강의 근거가 허용하는 범위에서 개념당 **3~6개**를 목표로 한다. 근거가 얇으면 적어도 되며, 근거 밖 내용을 채우지 않는다.
6. **유형 분포 목표(전체 기준):** 정의 25~30%, 목적·이유 15%, 원리 15%, 비교 15%, 한계 10%, 결과 10%, 판단 5%,
   계산은 강의에 공식·예시가 있을 때만.
7. v1의 좋은 QA는 문체만 고쳐 재사용해도 된다(같은 `concept_id`·근거 유지).

## 점검과 문서

  정의·역할 문항이 있는 개념 비율, 유형 분포. 기존 점검(길이, 두 버전 일치, 금지 페이지, unseen 개념, 중복)은 유지한다.
