# 평가셋 구축 프로토콜 (v1)

결정일: 2026-11-25. 공개 문서이므로 문항·정답 원문은 쓰지 않는다(원문은 `data_private/evalset/`).

## 원칙

1. **교수님 비공개 평가셋은 참고만 한다.** 공개 질문 11개의 **스타일**(짧은 한국어 질문, 질문 유형 분포)만 참고하고,
   공개 질문 자체나 그 변형은 평가셋에 넣지 않는다.
2. **혼합 방식:** AI 초안 → 자동 필터 → 변형 생성 → 사람 검증, 그리고 사람이 직접 쓴 소규모 문항으로 결과를 교차 확인한다.
3. **생성 모델 분리:** 평가 문항은 Claude가 쓰고, 학습 QA는 Codex가 쓴다(자기 선호·스타일 편향 완화).
4. **학습 데이터 생성 전에 동결한다.** 동결 후 해시를 기록하고, Held-out 문항은 Teacher 프롬프트에 넣지 않는다.

## 구성

| 세트 | 용도 | 규모 | 비고 |
|---|---|---:|---|
| `dev` | 모델·하이퍼파라미터 선택 | 150 | 학습 개념, test와 다른 질문 |
| `test_seen` | 본 결과(학습한 개념을 새 표현으로) | 200 | 용어 표기 변형 묶음 60문항 포함 |
| `test_unseen` | 일반화 분석(학습에서 뺀 개념) | 50 | 개념 25개 × 2문항. 논문 M1~M4 학습에서만 제외 |
| `human` | AI 문항 편향 점검 | 30~50 | 사용자가 직접 작성, test_seen 개념에서 |

과제 제출 모델은 unseen 개념까지 모든 개념으로 학습한다(과제 범위 손실 없음).

## 층화

- **영역(D01~D10):** 개념 가중치 = `log(1 + 강의 근거 페이지 수) × 깊이 계수`(core 1.5, supporting 1.0, mention_only 0.5).
  영역별 할당은 가중치 합에 비례하되 영역마다 최소 문항을 둔다.
- **질문 유형:** 정의 30%, 목적·이유 15%, 원리 15%, 비교 15%, 한계 10%, 결과(~하면 어떤 문제가?) 10%, 판단(항상 그런가?) 5%.
  CKU에 해당 내용이 없으면 정의·목적으로 대체한다(예: 혼동 개념이 없으면 비교 문항을 만들지 않는다).
- **용어 표기:** 한국어 용어 35%, 영어 용어 40%, 약어 15%(약어가 있는 개념만), 혼합 10%.
- **변형 묶음(CheckList식 불변성):** 한국어명과 영어·약어 표기를 모두 가진 개념 20개에 대해,
  같은 의도의 질문을 한국어 / 영어 / 약어(없으면 혼합) 표기로 3개씩 만든다.

## 문항 형식

| 필드 | 내용 |
|---|---|
| `question_ko` | 짧은 한국어 질문. 정답을 질문 안에 드러내지 않는다 |
| `reference_answer_ko` | 1~2문장, 30어절 이내. CKU v2.1과 강의 근거로 작성 |
| `key_points_ko` | 정답이 반드시 담아야 할 핵심 요소(1~3개) |
| `required_terms` | 답에서 영어 원어로 유지되어야 할 용어 |
| `question_type`, `term_form`, `domain`, `concept_id`, `variant_group` | 층화 정보 |
| `lecture_sources` | 강의 근거 페이지 |
| `writer`, `status` | 작성 모델, 검증 상태(`draft → auto_ok → human_accepted / human_edited / rejected`) |

## 자동 필터

1. 정답 길이: 30어절 이내, 1~2문장(`ktide.metrics`)
2. 정답 노출: 질문과 정답의 핵심 표현이 과도하게 겹치는 문항 제거
3. 중복: 문자 n-gram 유사도로 같은 세트 안의 거의 같은 질문 제거
4. 표기 일치: `term_form`과 질문의 실제 표기가 일치하는지
5. 답변 가능성: 다른 모델(Codex)이 질문만 보고 정답의 핵심 요소와 맞는 답을 낼 수 있는지,
   질문이 모호하지 않은지 점검(모호 판정 문항은 사람 검토로 보냄)

## 사람 검증

- `test_seen`, `test_unseen` 250문항 전체를 사용자가 검토한다(수용 / 수정 / 거절). `dev`는 자동 필터와 모델 검증만.
- 수용률·수정률·거절 사유를 기록해 논문과 보고서에 보고한다.
- 사용자가 직접 쓴 `human` 문항에서 모델 순위가 AI 문항과 같은지 확인한다.

## 분석용 태그

- M0(순정 모델)의 결과로 각 문항을 `known / unknown`으로 태그한다(Gekhman et al., 2024 방식 참고, 인용 전 원문 확인).
  지식 주입 효과와 용어 인식 효과를 분리해 분석하는 데 쓴다.

## 채점 정책 (비용·시간)

| 단계 | 세트 | 정답 기반 | 루브릭 | 반복 |
|---|---|---|---|---|
| 개발 중(모델·데이터 선택) | dev | O | 선택 | 1회 |
| 최종 비교(M0~M4, 과제 모델) | test_seen, test_unseen, human | O | O | 3회 |

- Codex 호출은 병렬(`--workers 4`)로 수행한다. 이미 존재하는 반복 결과 파일은 다시 호출하지 않는다.
- Judge 흔들림 추정은 최종 비교에서 한 번만 한다.
